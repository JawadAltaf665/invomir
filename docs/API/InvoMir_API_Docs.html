Authentication

All protected endpoints require a Bearer JWT token in the Authorization header: Authorization: Bearer <access_token>. Tokens are issued by POST /api/auth/login and expire in 15 minutes. Use POST /api/auth/refresh with the refresh token (httpOnly cookie) to obtain a new access token. Auth endpoints write security audit rows to audit_logs for register, login, refresh, forgot password, and reset password events. The Stripe webhook endpoint uses Stripe-Signature header validation instead of JWT.

POST /api/auth/register Create new user account PUBLIC ▾

Description

Creates a new InvoMir account. Sends an email verification link. User cannot send invoices until email is verified. A 14-day full-feature trial starts immediately on account creation.

Request Body · application/json

FieldTypeReqDescription

tax_percentnumberNoDefault tax % applied to invoices. Default: 0.

Responses

201Account created. Returns user object + access_token.
400Validation error — missing fields or weak password.
409Email already registered.

POST /api/auth/refresh Refresh access token using cookie PUBLIC ▾

Description

Issues a new access token using the httpOnly refresh token cookie. No request body required — the cookie is read automatically. The old refresh token is rotated (invalidated) and a new one is set.

Responses

200New access_token returned. Refresh token cookie rotated.
401Refresh token missing, expired, or revoked.

Response · 200

JSON
{ "access_token": "eyJhbGci...", "token_type": "Bearer", "expires_in": 900 }

DELETE /api/clients/{id} Delete client record JWT ▾

Description

Permanently deletes a client. Soft-delete is recommended — client is flagged as archived but invoice history is preserved for financial records. If client has active unpaid invoices, returns 409 conflict requiring resolution first.

Responses

204Client deleted (no body returned).
404Client not found.
409Client has unpaid invoices — resolve before deleting.

Note

⚠️ Deleted clients cannot be restored. All associated invoice history is archived (not deleted) to preserve financial records.

PUT /api/invoices/{id} Update draft invoice JWT ▾

Description

Updates a draft invoice. Only invoices in Draft status can be edited. Sent invoices must be cancelled and re-issued. Accepts the same body as POST /invoices. Full replacement of items array if provided.

Responses

200Updated invoice returned with recalculated totals.
400Invoice is not in Draft status — cannot edit.
404Invoice not found.

Business Rule

⚠️ Sent invoices are immutable. To correct a sent invoice: cancel it (DELETE /invoices/{id}), then create a new one. This preserves audit trail integrity.

POST /api/stripe/webhook Handle Stripe payment events STRIPE-SIG ▾

Description

Stripe's server-to-server webhook endpoint. Validates the Stripe-Signature header using the endpoint secret. Handles key events: payment_intent.succeeded marks invoice as Paid; payment_intent.payment_failed notifies user; customer.subscription.* events update plan status. Must return 200 immediately — processing is async via Hangfire.

Handled Events

EventAction
payment_intent.succeededMark invoice Paid, send receipt, cancel reminders, notify user.
payment_intent.payment_failedPush notification to user. Log failure.
customer.subscription.createdUpdate user plan to active.
customer.subscription.deletedDowngrade user to Free plan.
invoice.payment_failedNotify user of subscription billing failure.

Responses

200Always return 200 immediately. Stripe retries on failure.
400Invalid Stripe-Signature header.

Security Note

⚠️ This endpoint does NOT use JWT auth. It validates using Stripe-Signature header + your webhook secret via StripeClient.ConstructEvent(). Raw request body must be read before any parsing.

Sample Payload

JSON
{ "type": "payment_intent.succeeded", "data": { "object": { "id": "pi_3Nxyz...", "amount": 75600, // cents "metadata": { "invoice_id": "inv_01xyz..." } } } }
